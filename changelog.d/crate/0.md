### Fixed

- **`Svg::rasterize` blends what a document draws over itself in sRGB, as Chrome and the canvas do, rather than in linear light.** ([#0](https://github.com/l7aromeo/meo-skia-canvas/pull/0), [#728](https://github.com/l7aromeo/meo-skia-canvas/issues/728), [#804](https://github.com/l7aromeo/meo-skia-canvas/issues/804))
- **An SVG document's `href` names what `xlink:href` does -- an `<image>`, a `<use>` target, a gradient or pattern to inherit from -- and wins over an `xlink:href` beside it.** ([#0](https://github.com/l7aromeo/meo-skia-canvas/pull/0), [#734](https://github.com/l7aromeo/meo-skia-canvas/issues/734))
- **On Linux, `Context2D::measure_text` and every drawn run advance each glyph by its font units times the size, as macOS and Windows do, rather than about 2/65536 px an em over at 16px in a 1000-unit face, with the patched Skia archives.** ([#0](https://github.com/l7aromeo/meo-skia-canvas/pull/0), [#695](https://github.com/l7aromeo/meo-skia-canvas/issues/695))
- **An SVG document's paint in any CSS Color 4 form -- `color()`, `oklch()`, `#rrggbbaa`, space-separated `rgb()`, `transparent` -- is the colour it names, as a `fillStyle` reads it, and a `currentcolor` in lower case is the `color` it inherits, where both drew black.** ([#0](https://github.com/l7aromeo/meo-skia-canvas/pull/0), [#815](https://github.com/l7aromeo/meo-skia-canvas/issues/815))
- **An SVG document's translucent `flood-color` keeps its own alpha, multiplied by `flood-opacity` as Filter Effects says, where it drew opaque, with the patched Skia archives.** ([#0](https://github.com/l7aromeo/meo-skia-canvas/pull/0), [#815](https://github.com/l7aromeo/meo-skia-canvas/issues/815))
- **An SVG document's `<line>` paints no fill, since a line has no interior, as Chrome draws it, where its fill -- black unless set -- drew as a hairline along it, with the patched Skia archives.** ([#0](https://github.com/l7aromeo/meo-skia-canvas/pull/0), [#825](https://github.com/l7aromeo/meo-skia-canvas/issues/825))
