    Type Alias CompositeExtension

    CompositeExtension: "clear" | "destination" | "modulate"

    🧪 The three composite operators this build accepts that the standard does not list. Skia blend modes, and none has a standard equivalent.

    Separated from CanvasCompositeOperation so a caller can see which half of the API they are relying on: code using only the standard names moves to a browser canvas unchanged, and code using one of these does not. The standard's own rule is that an unlisted value is ignored, so a browser given one of these does nothing rather than failing loudly.

    If the standard adopts one, its name moves to CanvasCompositeOperation and nothing else about it changes -- which is the reason the two are separate types rather than one annotated list.

    Type Declaration

    • "clear"

      Leaves the pixel fully transparent wherever the source is drawn, regardless of the source's own alpha.

      "destination-out" is the nearest standard operator and erases in proportion to the source's alpha instead: over rgba(255,128,0,0.8), a rgba(0,128,255,0.5) fill leaves 0,0,0,0 here and 255,127,0,102 there.

    • "destination"

      Keeps the destination and ignores the source entirely, so the draw has no effect on the pixels it covers.

      The counterpart to the standard's "copy", which keeps the source and ignores the destination.

    • "modulate"

      Multiplies source and destination componentwise including alpha, which is what separates it from the standard's "multiply".

      Over rgba(255,128,0,0.8), a rgba(0,128,255,0.5) fill gives 0,65,0,102 here -- alpha 0.8 x 0.5 -- against 113,99,29,230 for "multiply", which composites alpha the ordinary way.
